Where this goes next

Not a snapshot of the past — this is the live backlog. Pulled from two independent AI research passes (Gemini + ChatGPT) run against the real codebase, cross-checked against what's actually already built.

Just Shipped

  • Native 1-10 ratings + "Mark Watched," kept separate from TMDB's score — the #1 thing both AI reports independently flagged as the biggest missing feature
  • Hot Takes integrity fix — split into "Community" (real visitors only) and "Character Chaos" (the bot threads), so neither is mistaken for the other
  • Soft-404 fix — every URL used to return HTTP 200 even when broken; real routes now 404 properly, dead entities get a client-side noindex signal
  • Batched, cached watch-provider badges on both movies and TV, comment-count badges site-wide
  • Real SEO basics — meta tags, favicon, sitemap, per-page titles, TMDB attribution
  • Bot roster trimmed 108 → 72, voice profiles reconciled, then 8 major threads scaled to ~20 comments each (130 new comments, zero failures)
  • A persistent research cache for the bot-comment pipeline, so repeated research passes stop re-verifying the same facts from scratch

Building Now

  • Styling pass on the new ratings/watched widget (done — real star glyphs, matching panel styling)
  • docs/persona-ensemble-framework.md — turning this session's bot-comment methodology into a project-agnostic, reusable reference (Layer 1 of a planned doc → Skill → code-template progression)
  • Reddit-style Wilson-score ranking under consideration for Hot Takes, now that the human/bot split exists
  • Using the unused likedBy/dislikedBy vote data as a feedback signal for which bot comment styles actually land

Ideas & Backlog

  • Real person/cast pages via TMDB's combined-credits endpoint — clicking an actor currently dead-ends
  • Franchise/collection pages (TMDB already has this data — Alien, John Wick, etc. — MCU stays hand-curated since it's richer)
  • "On my services" personalized filtering, once watch-provider data has a reason to be personal instead of just a badge
  • append_to_response consolidation on the main movie-detail route (4 TMDB calls → 1) — real but low-urgency engineering cleanup
  • Box-office $ amounts on cards — needs a one-time-extraction-plus-permanent-cache approach, since TMDB's list endpoints don't include revenue
  • A standalone "lessons for future projects" doc — the transferable patterns from this build (multi-session AI workflow, batch-and-cache, synthetic-vs-real data provenance), written so they outlive this specific app

Last updated alongside the live project — ask for a refresh any time the backlog moves.
